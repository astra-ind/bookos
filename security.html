Security

Last updated: September 2026

Architecture

BookOS is an Electron desktop application with a hard process boundary: the interface runs in a sandboxed renderer with contextIsolation enabled and Node integration disabled. All filesystem, database, and provider operations happen in the main process and are reached only through an explicit, enumerated bridge. The renderer never touches the disk directly.

Credentials

AI provider API keys are stored in the operating system's credential vault — Windows DPAPI, macOS Keychain, or libsecret. They are never written to the project database, never included in backups, never logged, and sent only to the provider they belong to. Masked values are shown in the interface; the smoke suite asserts that raw keys never persist to disk.

Data at rest

Books are plain folders on your disk — deliberately so. There is no server, no account database, and no cloud copy. Availability and confidentiality of your writing reduce to the security of your own machine and whatever backup arrangements you choose.

Network

The application makes no telemetry or analytics calls. Outbound requests occur only when you invoke AI features (to your configured providers) or check for updates, if enabled. Everything else — writing, search, continuity audits, semantic indexing, exports — runs locally.

Reporting

Found something? Email support@bookos.app with details. During development we can't run a bounty program, but we will credit responsible disclosures in the changelog.
